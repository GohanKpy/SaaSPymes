## Bugs encontrados y corregidos en la misma corrida (dentro del alcance aprobado)

1. **Crash en cancelar/cambiar con id inválido** — `ownFutureAppointment` pasaba
   `appointmentId: "1"` a Prisma → stack de error como resultado de la
   herramienta → "No pude encontrar el turno". Fix: validación de UUID con
   error accionable. **Severidad alta** (bloqueaba el cambio de turno).
2. **El modelo usa números de orden como id** (3 de 3 reservas mandaron
   `serviceId: "2"`/`"3"`/`"1"`; el cambio de turno `appointmentId: "1"`). Se
   autocorregía por el error accionable, gastando una llamada extra. Fix: las
   herramientas devuelven `service_id` / `appointment_id` con el MISMO nombre
   que el parámetro que los consume, y la regla 2 dice "textual, nunca un
   número de orden". Re-verificado: caso 4b y cambio de turno sin errores.
3. **Dato inventado** ("tenemos estacionamiento") — regla 5 ampliada: lo que
   no figura en datos ni herramientas no se afirma ni se niega; se deriva.
4. **Nombre no registrado** al presentarse junto con otro pedido — regla 6:
   `save_customer_name` en el mismo turno, antes de responder.
